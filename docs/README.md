## 工具链（`tools/`）

- **`patches/`（67 个）**：每轮改动的 Python 补丁脚本。命名沿革 `_fix3.py … _fix54.py`，另有少量专项脚本（`_audit1.py`、`_fix_tut.py`、`_fixwidth.py` 等）。
  - 统一形态：**先断言锚点唯一命中 → 改文本 → 全局版本号替换 → 写回 CRLF → 复核结构不变量**；全部支持 `--dry` 干跑，断言失败即中止且不落盘。
  - 0.4.12 起补丁流程前置 **`node --check` 语法预检**：同类"字符串拼接漏 `+`"错误已出现两次，干跑只能验锚点、验不了语法。
- **`verifiers/`（14 个）**：Node 回归验收脚本。`_verify39.js` → `_verify54.js` 逐版对应，另有 `_csschk.js`、`_symchk.js` 两个专项探针。
  - 核心手法：**抠出 CSS 装配区真实求值**（而非 grep 字符串），断言花括号深度归零、字面 `\n` 污染为 0、级联顺序正确。
  - 0.4.12 起加**全局崩溃兜底**：任何意外异常也先把报告落盘再退出，否则"崩了且没报告"等于没有凭据。
  - 0.4.12 起路径全部由 `__dirname` 推导、报告落在仓库内、对照基线按 SHA256 钉死：**验收脚本自身必须可复现**，不能依赖临时工作区散件。
- **`release/`（4 个）**：发布链路。打包（`_rel54.py`）→ 包内校验（`_zipchk.py`）→ 版本链凭据（`_chain54.js`）→ **版本库层行尾验证**（`_gitverify.py`）。
- **`housekeeping/`（5 个）**：工作区卫生。留底 + 清理（`_housekeeping.py`，六条硬规则）→ **留底覆盖核对**（`_zipcov.py`）→ **收尾现状核对**（`_vault.py`）。事故复盘见该目录 `README.md`。

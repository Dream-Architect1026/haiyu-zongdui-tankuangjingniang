## 0.4.3 — 为什么"改了代码界面一点没变"

**现象**：布局改造已落盘、字节数与标记都核对无误，但用户看到的面板与改造前完全一致。

**定位过程**（否掉了三个假设后找到真因）：

| 假设 | 否证方式 |
|---|---|
| 文件损坏 | 逐标记计数 + Node 逐字节扫行尾，26/23 个标记齐全、CRLF 正常 |
| 用户装错文件 | 用户明确否认；且该假设无法解释"标记全在却无变化" |
| 浏览器缓存里可搜到 | 目标存储为 LevelDB + snappy 块压缩，531 个文件扫描命中 0 |

**真因**：旧版本挂载宿主是**零属性裸 `div`，且无任何去重护栏杆**；新版本靠 `data-hx-panel` 去重。两者判据不同 ⇒ 互相"看不见"对方 ⇒ 同时启用时**各挂一个面板**。两个面板都是 `position:fixed`、同坐标同尺寸，**后挂的完整画在上面**——旧版后挂时严丝合缝盖住新版。

**修法**：run-id 去重（宿主属性写本次运行 id）+ 挂载后多轮清场（`0/600/1500/3200ms`，非自身面板与历史裸宿主一律 `display:none`，**隐藏不删除**）+ 自身宿主移到 `body` 末尾 + 控制台自报 `__HX_BUILD__` / `__HX_DIAG__()`。

**教训**：闭式 Shadow DOM 外部探不到内部结构，**必须让脚本自己报告状态**，不能靠外部查询。

## 0.4.4 — 液态玻璃与"看不见的光带"

**光带为什么看不见（本轮埋下、0.4.8 才真正解决）**：`.main-page{position:fixed}` 且**子节点全是 fixed** ⇒ 它自身的盒子是 **0×0**，`::before{inset:0}` 等于画在 0×0 上。

**标签条改造**：外层容器去掉玻璃底（去 dock），每个标签独立胶囊；三态（静止 / 悬停 / 吸顶滚动），滚动态由监听 shadow 内 `scroll` 切换（`scrollTop>4`）。

**用量栏**：移除版本号（连 CSS 规则一起删，残留 0），替换为「本次」= 本次启用脚本后的累计花费；基线存 `sessionStorage`，同标签页刷新 / 跳转沿用，点击可重置。上方总计口径不动。

## 0.4.5 — 作答态图片消失（flex 收缩）

**证据链**（截图 OCR + 逐像素）：

- 截图里半句是 `急，马上就好`，原文 `主人别急，马上就好` ⇒ **左边「主人别」被裁掉**
- 文字左缘落在 x=26（2x px），居中排布应落在 ~x180 ⇒ **内容确实溢出并向左溢出**

**机制链**：

1. 作答态 hero 切 `flex-direction:row`，但第三个子节点「余额块」**仍带 `width:100%`**（当初只设了 `height:0`，漏了宽度）
2. 该行内容宽 ≈ `44(头像) + 9 + 气泡 + 9 + 整行宽` ≈ 容器的 **1.7 倍**
3. 容器保留基类 `justify-content:center` ⇒ 溢出向左右均分，首个子项被推到 x<0
4. `<img>` 是 flex 项、默认 `flex-shrink:1`，而气泡 `min-width:auto` 顶住不缩 ⇒ **赤字全由图片独自吸收，44px 被压成 0 宽**
5. 外层 `.el-card__body{overflow:hidden!important}` 再一裁 ⇒ 图彻底不可见

**修法**：余额块**退出行宽预算**（`flex:0 0 0px; width:0; min-width:0; height:0; overflow:hidden; pointer-events:none`，零尺寸但**仍可过渡动画**，优于 `display:none`）；头像 `flex:0 0 auto` 永不收缩；气泡改为让步方 `flex:0 1 auto; min-width:0`。修后整组宽 194 < 可用 286，图片完整落在 x=46..90。

**教训**：**"图片消失"先查 flex 收缩，别先怀疑图裂**。口诀：谁抢宽度 / 谁该让步 / 谁不能缩。

## 0.4.6 — 最小化不跳变

写死高度会因标题栏实际高度差几像素而裁切。改为**实测**标题栏高度写入 CSS 变量 `--hx-min-h`，卡片按变量收合并以 `height .32s` 过渡 ⇒ 尺寸严丝合缝。

**状态灯初版**：绿=运行中 / 黄=答题中 / 红=已终止。此版判据有缺陷，0.4.10 重写。

## 0.4.7 — 背景脉动光

**约束**：光带必须在内容之下、不吃点击、且**不能溢出面板**。

**做法**：只用 `background-position` 扫掠（**规则体内不出现 `transform`**），配 `z-index:-1` + `pointer-events:none`；周期 9.6s（刻意压低刷新率）。另加 13s 顶部柔光呼吸。

**验收专项断言**：①必须用 `background-position` 方案；②规则体不得含 `transform`（否则会越出面板）；③`z-index:-1`；④`pointer-events:none`；⑤周期 ≥8s。

> 同一轮还确立了：`.whale-hero` 是 flex 容器，其 `::before/::after` **必须绝对定位**，否则会变成 flex 项撑破布局——与 0.4.5 是同一族坑。

## 0.4.8 — 光带终于可见

把光带从 0×0 的 `.main-page` 搬到**有实际尺寸的 `.el-card`**：`.el-card::before` 做模糊色层（13s 呼吸），`.el-card__body::after` 做自上而下扫掠。同时 `.el-card{background:transparent; backdrop-filter:blur(20px) saturate(156%)}` 完成玻璃化。

## 0.4.10 — 状态灯"运行中却显示已终止"

**真因**：旧判定 = 「最近 6 条日志里只要有 `danger`/`error` 级就判红」。而 `danger`/`error` 是**日志等级**，与"脚本是否在运行"**毫无因果关系**——脚本日常就吐三条 danger 噪音（没捞到题目 / 自动翻题关掉了 / 这页没活儿歇会儿），**只要在运行就必然判红**。

**新判定（优先级明确）**：

1. 有题目在答 → **黄**
2. 否则自最新一条往前扫 24 条：先匹配恢复/开工词 → **绿**；再匹配已停止/失败/未配置词 → **红**；两不命中 → **绿**

**验收方式（本轮确立）**：为该判定做**真值表**，并**保留旧逻辑作对照项**跑同一批输入，确认「旧逻辑判 stop（错）、新逻辑判 run（对）」—— 证明改动确实起作用，而不是只断言"某字符串存在"。

**"背景太透、想要边框玻璃质感"的真因**：`.el-card` **从来没有 `position`** ⇒ `::before`/`::after` 全挂到 0×0 的 `.main-page` 上（这正是 0.4.4 那条光带看不见的同一个根因）。补 `position:relative` 后，1px 冷蓝描边 + `::after` 双层内高光做玻璃边，光带与扫掠也终于落在卡片真实盒子上。

**光晕统一 ×0.618**：`.30→.185 / .95→.587 / 0→0 / .88→.544 / .45→.278 / .70→.433`（保留 3 位，逐项核对）。

**好感度卡片不显示的真因**：注入节点是 Vue 模板 div 的子节点，**Vue 一重渲染就把它移除**。改为四级降级选落点 + `MutationObserver` 发现被移除立刻补回 + 多次延时 ensure + 定时轮询兜底。

**防静默失效**：好感度需读累计花费，但该 store 离注入点 7000 行、作用域不敢赌 —— catch 之后**直读存储兜底**并自带金额格式化；即使真取不到，探针里也能立刻看见，不会伪装成"永远 Lv.1"。

## 0.4.11 — flex 行的定位归因

**现象**：为美化把 label 收成小胶囊后，本行的调节控件**从右侧跑到了左侧**。

**机制**：该行是 `display:flex`，原本 label 为 `flex:1 1 auto`，**靠 label 占满剩余宽度**把控件自然顶到右边。label 改成 `flex:0 0 auto` 后一收缩，"顶"的力量消失，控件紧跟 label 站到左半区。

**修法**：显式给 `.el-form-item__content` 加 `margin-left:auto`，不再依赖 label 宽度定位。

**顺带**：去掉四项数值参数的必填星号时，**只隐藏 `::before` 而不删 `required`** —— 因为包裹标题的小胶囊正是靠 `.is-required` 选中的，删属性会连胶囊一起消失。

## 0.4.12 — 「本次」为什么不归零

**现象**：用量栏「本次」在关掉脚本再打开后仍显示上次的值（用户实测 20），只有手动点击才归零。

**定位（两步，都是"字段生命周期读错"）**：

| 症状 | 真因 |
|---|---|
| 重新启用不归零 | 基线存 `sessionStorage`。它的生命周期是**标签页**而非**脚本实例** —— 关掉脚本再打开，同一条基线仍被读回，于是 `本次 = 累计 − 旧基线`，差值永远是旧账 |
| 点了没反应 | 重置处理绑在 `.usage-session` 上，而该元素在 0.4.10 用量栏改版时**已被删掉** ⇒ 绑定是死代码；且没有 `cursor:pointer`，用户根本不知道能点 |

**修法**：基线改**内存变量**。脚本每次启动都从当前累计值起算，「本次」语义 = **本次启用脚本后的用量**，与同栏「运行」（本次运行时长）同源同界。交互上给「本次」格补 `data-hx-cell="session"` 标记，点击绑定改挂到标记上，并补手型 + 悬停 + 按下反馈。

**方法论收获**：这类"状态机跨界"的 bug，**字符串存在性断言完全失效**（`resetSessionUsage` 确实存在、`sessionStorage` 确实被写过 —— 全都"看起来对"）。必须**抠出新旧两块代码分别真跑**，喂同一串事件，看输出在哪一步分叉。旧块给出 20、新块给出 0 —— bug 与修复同时被证明。

**流程收获（两个坑，各吃一轮）**：

1. **干跑通过 ≠ 语法正确**。追加的 CSS 块里一行漏了字符串拼接的 `+`，两个字符串相邻 ⇒ 整文件解析失败；而干跑只验锚点与结构不变量。⇒ 落盘前加 `node --check` 预检。
2. **验收脚本崩了且报告没落地 = 白跑**。一次因抽块函数读到未同步的旧副本而抛错，异常直接出栈，报告文件都没生成。⇒ 加全局崩溃兜底，先把已收集结果写盘再退出。

## 复用经验沉淀

以下条目已沉淀进个人技能库（`vue-userscript-style-debug`），避免重复踩坑：

**布局 / CSS**

- 图片"消失"先查 flex 收缩；flex 容器上的伪元素必须绝对定位
- 伪元素宿主必须先量盒子：`position:fixed` 且子节点全 fixed 的容器盒子为 0×0
- "把控件顶到右边"默认靠左侧元素 `flex-grow` 撑出来；左侧一收，布局整体左塌 ⇒ 改右侧 `margin-left:auto`
- CSS 动画打不过 `!important`（`!important` 同样压过动画，会在"修样式"时误杀呼吸动画）
- 判定型逻辑（状态灯等）的验收必须做**真值表 + 旧逻辑对照**，只 grep 字符串等于没验
- 跨"脚本实例生命周期"的状态**不要放 `sessionStorage` / `localStorage`**：前者是标签页级、后者是域名级，都不随实例启停归零；实例级语义用**内存变量**
- 给已改版过的 UI 补点击交互前，**先确认选择器还在**：旧绑定可能是死代码，且没有手型的死绑定用户根本感知不到

**构建 / 校验**

- `.user.js` 必须 CRLF，裸 LF 归零；**行尾与字节数以 Node 逐字节扫为准**，PowerShell 的同类正则曾假报 `bareLF=12`
- CSS 装配验收要**真实求值**（抠出装配区、桩掉外部标识符、`new Function` 跑一遍），断言括号深度、字面 `\n` 污染
- **干跑（锚点/结构）挡不住语法错**：文本改动的落盘前预检必须包含 `node --check`；字符串拼接漏 `+` 会让整文件解析失败而其他检查全绿
- **验收脚本必须有全局崩溃兜底**（先落盘报告再退出）：一旦抛错，没落地的报告等于没有凭据，还会误判成"没跑"
- **改活动副本后要同步仓库副本再审**：验收脚本读的是仓库副本，只改活动副本会让验收看到旧内容并抛错
- 改完文件先量**字节数**再断言：`len(str)` 数的是字符不是字节，中文一个字 3 字节，误用会得到"文件被改坏"的假警报
- 版本号全局替换会**连带把旧分节注释一起改名**，造成两个块同名；需给旧注释加后缀区分
- 期望值别硬编码出现次数（新增内容往往自带版本号），改为按实际计算或退为 `>= N`
- **同一文件并发发多个编辑会互相覆盖**（3 个只活 1 个，且都报成功）—— 串行执行
- Python 匹配源码里的 `\u2014` 等字面转义文本必须用 raw string

**取证**

- 闭式 Shadow DOM 外部探不到 ⇒ 让脚本自报 `__HX_BUILD__` / `__HX_DIAG__()`
- 浏览器存储（LevelDB）有 snappy 块压缩，**扫描文本不可靠**，不要在此浪费轮次
- 取证脚本一律 **ASCII-only**（PowerShell 5.1 会把无 BOM 的 UTF-8 `.ps1` 按 ANSI 解析，中文变乱码并静默产出 0 行）
- 同一文件并发编辑会互相覆盖；PowerShell 重定向默认写 UTF-16，需显式指定编码

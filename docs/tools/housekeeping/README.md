# 整理与留底工具（housekeeping）

第四轮（0.4.12）整理时，`_clean54.py` 因**被重复执行且原地覆盖留底包**，导致 46 个散件未及压缩就被删除（详见 `_manifest-round4.json` 的 `incident` 段）。这里给出**修正版** `_housekeeping.py`，把事故教训固化成四条硬规则。

## 四条硬规则

| # | 规则 | 对应事故原因 |
|---|---|---|
| 1 | **留底包名带唯一后缀**（`-<时间戳>`），永不原地覆盖 | 第二次执行把第一次的包覆盖，46 个条目彻底丢失 |
| 2 | **清单先落盘，再执行删除** | 崩溃时清单没写，事后无法追溯删了什么 |
| 3 | **删除逐项记账，支持断点续跑** | 中途崩溃后无法判断哪些已删、哪些未删 |
| 4 | **重跑前检查目标是否已存在**（幂等） | 无幂等设计，重复执行＝二次破坏 |

## 用法

```bash
# 干跑：只列计划，不改盘
python _housekeeping.py --ws <工作区> --archive <归档目录>

# 执行
python _housekeeping.py --ws <工作区> --archive <归档目录> --apply
```

## 与发布链路的关系

`docs/tools/release/` 负责**发布**（打包 + 校验），本目录只负责**工作区卫生**（留底 + 清理）。两者都会产出可复核的报告，落在 `docs/reports/`。

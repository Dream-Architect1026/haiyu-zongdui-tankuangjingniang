# 验收方法论与凭据

本文件记录 0.4.x 每轮改动**如何被验证**。所有数字均来自 `reports/` 下的原始报告，可用同目录 `tools/verifiers/` 脚本复现。

---

## 一、四条基础校验（每轮必跑）

| # | 检查 | 方法 | 判据 |
|---|---|---|---|
| 1 | 语法可解析 | Node `--check` 或 `new vm.Script(src)` | 退出码 0 / 无异常 |
| 2 | 行尾合规 | **Node 逐字节扫**（不是 PowerShell 正则） | `bareLF == 0` |
| 3 | CSS 装配可求值 | 抠出装配区 → 桩掉外部标识符 → `new Function` 真跑 | 花括号终值深度 `0`；字面 `\n` 污染 `0` |
| 4 | 版本号自洽 | 全局替换后统计 | 旧版本号残留 `0`；新版本号出现次数 = 计算值 |

> **为什么必须 Node 逐字节**：PowerShell 的同类正则在同一个文件上曾假报 `bareLF=12`，而 Node 逐字节扫是 `0`。行尾/字节数以 Node 为准。

## 二、专项验收手段（随问题演化新增）

### 1. 级联顺序断言（0.4.5 起）

**目的**：专治"改了没效果"。CSS 靠后写覆盖靠前，但若顺序反了，新规则会被旧规则压住。

**做法**：断言「新规则的字符偏移量 > 被覆盖的旧规则偏移量」。0.4.10 起覆盖 11 组级联关系。

### 2. 真·CSS 级联求解器（0.4.11 起）

**做法**：把新块与所有历史块按出现顺序喂进求解器，逐一算出**最终生效值**，再断言语义目标：

- 胶囊配色 = 常规玻璃色（而非粉红）
- 必填星号 = 隐藏
- `.el-form-item__content` 的水平定位 = 右端

**修过的一个匹配器缺陷**：`::before` 规则曾被误算到元素本体上，导致假 NG。

### 3. 判定逻辑真值表 + 旧逻辑对照（0.4.10 起，0.4.12 复用）

**适用的前提**：被验的是**逻辑读错字段 / 状态机跨界**这类 bug —— **只断言字符串存在等于没验**。

**0.4.10 状态灯**：

| 输入 | 新逻辑 | 旧逻辑（对照） |
|---|---|---|
| 全部 danger/error 日常噪音 | `run` ✅ | `stop` ❌ |
| 启动 + 翻题 + 噪音 | `run` ✅ | — |
| 最新一条为"脚本已停止" | `stop` ✅ | — |
| 有题目在答 | `busy` ✅ | — |
| 终止后又"重新潜入" | `run` ✅ | — |

**0.4.12「本次」用量**（同法：抠出新旧两块代码**分别真跑**，喂同一串事件）：

| 事件（累计值） | 新逻辑（内存基线） | 旧逻辑（sessionStorage 基线，对照） |
|---|---|---|
| L1 首次加载（累计 0） | `0` ✅ | `0` |
| L1 答题后（累计 20） | `20` ✅ | `20` |
| **L2 重新启用（累计 20）** | **`0` ✅** | **`20` ❌** |
| L2 再答一题（累计 26） | `6` ✅ | `26` ❌ |
| L2 点击归零（累计 26） | `0` ✅ | `0` |

保留旧逻辑作对照项，是为了证明**改动确实起作用**：同一串输入下，旧逻辑在「重新启用」这一步给出错误答案 `20`，而这正是用户报的现象。

> **"抠出来真跑"而非"读代码推断"**：两块代码都是从源文件里做括号配对抠出的原文，在 `new Function` 里跑出来的；`sessionStorage` 用内存桩替代，以模拟"同一标签页内关闭再打开脚本"的存储存活行为 —— 这正是旧逻辑出错的机制本身。

### 4. 数据字面量真实求值（0.4.9 起）

好感度档位是纯数据，容易被"看起来对"骗过。做法：把 `HX_FAV_TIERS` 字面量按括号配对抠出来真跑一遍，断言：

- 5 级 / `at = [0,1,2,5,10]`
- 每级 10 条 / 合计 **50** 条
- 每条以 `{n}` 占位开头
- **50 条无重复**

### 5. 结构不变量断言（贯穿）

只锁**结构性不变量**（定义数 = 1、调用数 = 1、旧串 = 0、`bareLF == 0`），不硬编码"某字符串出现 N 次"——注释里的一次出现就会误报。

> 计数用于**打印**，断言只用于不变量。

## 五、复现方式

```bash
# 语法检查
node --check "海底小纵队·探矿鲸娘.user.js"

# 跑某一轮验收（以 0.4.12 为例）
node docs/tools/verifiers/_verify54.js
```

补丁脚本均支持**干跑**（`--dry`）：只校验锚点唯一性与结构不变量、打印每处版本号上下文，**断言失败即中止且不落盘**。真实写入前一律先干跑，再备份现行版，最后写入并复跑验收。

> 0.4.12 流程补充了一条：**落盘前先 `node --check` 语法预检**。本轮干跑已通过、锚点全中，但追加的 CSS 块里有一行漏了字符串拼接的 `+`，两个字符串相邻 ⇒ 整份文件语法失败。干跑验的是锚点，验不了语法；预检把这类错误挡在落盘之前。
> 本轮还补了验收脚本的**崩溃兜底**：一次因抽块函数抛错而"崩了且报告没落地"，等于白跑 —— 现在任何异常都会先把已收集的结果写盘再退出。

### 5.1 验收脚本自身必须自洽（0.4.12 修订）

清理工作区时踩到一个真实缺陷：`_verify54.js` 把路径写死成工作区绝对路径，对照基线指向 `_bak_0411.user.js`——那是**临时工作区散件**。散件一清理，脚本立刻 `ENOENT` 崩掉，回归能力凭空消失。

**收尾清理前必须先确认没有产物依赖待删文件。** 现在该脚本：

- 路径全部由 `__dirname` 推导（`../../..` = 仓库根），仓库换位置、换机器都能跑；
- 报告写到仓库内 `docs/reports/_v54out.txt`（随仓库一起版本化，不再落在临时工作区）；
- **对照基线锁定仓库内权威快照 `docs/versions/v0.4.11.user.js`**，并以 SHA256 + 字节数双重钉死——防止"随手抓一个旧文件当基线"导致对照静默失效；
- 保留旧路径作为兜底候选（`find(existsSync)` 取第一个命中），历史工作区还在时也能跑。

## 六、版本库层的行尾保证（0.4.12 起）

`.user.js` 必须 CRLF 是硬约束，但 **git 默认会对文本文件做行尾转换**：工作区是 CRLF，blob 里存成 LF。后果是——**从托管平台"下载 zip"或 `git archive` 拿到的脚本是 LF 版本**，与约束不符。

修法：新增 `.gitattributes`，对 `*.user.js` 设 `-text`（禁用一切行尾转换），让 git 逐字节存原文件。索引、检出、导出三处都是 CRLF。

| 层面 | 校验方式 | 结果 |
|---|---|---|
| 工作区文件 | 逐字节统计 | 639440 字节 / CRLF 8965 / 裸 LF **0** |
| **git 对象层** | `git cat-file blob HEAD:<file>` | 与工作区**逐字节相同**，SHA256 一致 |
| **导出层** | `git archive --format=zip` 内嵌文件 | 与工作区**逐字节相同**，SHA256 一致 |
| 历史快照 ×9 | 对象层 vs 工作区逐字节比对 | 9/9 一致，零裸 LF |

**约束适用范围（本节予以精确界定）**：

| 类别 | 位置 | 是否硬校验 |
|---|---|---|
| **发布件** | 仓库根 + `versions/` | 是（裸 LF 非 0 即失败） |
| **工装件** | `bisect/`、`repro/` | 否 —— 当年二分定位与复现用的本地候选构建，按"不篡改历史证据"原则**保留原貌** |

> 为什么不一并转成 CRLF：这些是**证据**，不是交付物。改写字节等于篡改取证对象；且它们从未作为发布件分发。

复现：`python docs/tools/release/_gitverify.py`

## 六之二、清理动作怎么验（0.4.12 收尾）

清理是**唯一会真删东西**的环节，所以它需要比补丁更硬的凭据。0.4.12 收尾轮把"清干净了"拆成三条可复核断言。

### 1. 删掉的每个文件都确实躺在归档包里（`_zipcov.py`）

不信"我打包了"，而是**逐名 + 逐字节**：遍历归档目录下所有 zip，对 `ledger.json` 的每一条记录，找出含同名条目的包并比对 SHA256。

| 判据 | 期望 |
|---|---|
| 覆盖 | ledger 去重后 46 个文件名，全部能在某个归档包内找到 |
| 完整性 | 包内解出的字节 SHA256 与 ledger 记录**逐条一致** |

### 2. 工作区真的空了、资产真的都在（`_vault.py`）

最后一步不该是"我觉得清干净了"，而是一份现状快照：每个工作区还剩什么（含隐藏目录，`.workbuddy` 必须保留）、关键资产是否齐全、**台账是否自洽**。

台账自洽的判据是 `journal.deleted`（去重）应等于 `ledger` 去重名单：
- 删除数 **>** 归档数 ⇒ **删了没留底**，数据真丢 → 失败
- 删除数 **<** 归档数 ⇒ **留底了没删**，垃圾堆积且欺骗台账 → 提示跑 `--finish`

这一条不是理论：本轮真实撞上过——台账记 32 条"已归档"，盘上 31 个文件还在。根因是幂等判据用了 `ledger.entries`（归档**尝试**）而非 `journal.deleted`（确认删除），而 ledger 在打包**之前**落盘，进程在两者之间中断就会留下这种"文件还在但被判为已完成"的死角。

### 3. 修复已发生的断裂：`--finish`

对"台账已记但文件仍在盘"的条目，**先在归档包内按名找到并核对 SHA256**，一致才删，且不重新打包（避免 8MB 级重复留底）。本轮用它补删 31 个文件，全部 0 保留。

### 4. 顺带发现的第二例同类缺陷

按"删前查依赖"扫仓库时，机械捕获到 `docs/tools/release/_gitverify.py` 仍把路径写死在临时工作区——和 `_verify54.js` 是同一个病。两个脚本已一并改为 `__dirname` 自解析，并加**仓库根自检断言**（层级数算错会当场抛错，而不是生成 `docs/docs/reports/...` 这种鬼路径跑到写文件才失败）。

### 附带教训：清完的目录别再往里写日志

本轮收尾脚本把日志写在**正在被清理的工作区内**，导致"写日志 → 被清扫器删掉 → 又写回来"的循环。已改为写系统临时目录。清理工具的目标目录应视为只读。

复现：`python docs/tools/housekeeping/_zipcov.py` 与 `python docs/tools/housekeeping/_vault.py <工作区...>`

## 七、局限（已知未验证项）

- **视觉效果无法在本环境亲眼确认**（无法读图）。背景光带浓淡、玻璃模糊强度、动画节奏等均按"能看见但不抢戏"的中间值给定；如偏淡/偏重，调 alpha 与周期即可。
- 动画的**真机流畅度**未经性能测试（面板已加 `prefers-reduced-motion` 降级）。
- 面板为**闭式 Shadow DOM**，外部脚本无法探测内部结构；所有自查依赖脚本自身的 `__HX_*` 探针。
